## How to use this report

- **Lessons L1-L12** (§1) are the answer. Each has a verdict: **ADOPT** (take it; the row says when and in what form), **CONSIDER** (decide at the named trigger), **ALREADY DONE** (the plan or design has it), or **REJECT** (do not take it into ep9).
- **Follow-up ids LRN-01 to LRN-15** (§5) are orchestrator routes. A later plan or ADR edit that takes one cites [R19] and the LRN id. This report does not change the plan or any ADR.
- **Source tags** `dotnet Fnn`, `kotlin Fnn` and `dart Fnn` name one verified finding. Appendix A has each one: the claim (the corrected text where the verifier corrected it), its sources and its verdict.
- **Raw evidence**: [artifacts/vm-lessons/](artifacts/vm-lessons/README.md) holds the researchers' and verifiers' JSON (`findings.json`).
- **ep9 short forms**: D13 = [docs/plan/13-execution-modes.md](../plan/13-execution-modes.md), Pnn = `docs/plan/nn-*.md`, Hnn = `docs/adr/Hnn-*.md`, DL = [docs/decisions-log.md](../decisions-log.md), R11/R14/R17 = [11](11-dual-mode-vms.md)/[14](14-dual-mode-architecture.md)/[17](17-aot-refutation.md) in this folder. `H33:25-35` means lines 25-35 of H33 at `m9-p5`. To read a cite later, use `git show m9-p5:<path>`; the lines move as the files grow.

## 1. One-page answer: 12 lessons

| # | Lesson | Shown by | Evidence | ep9 touch point | Verdict |
|---|---|---|---|---|---|
| 1 | Do not re-tier hot optimized AOT code through an *unoptimized* instrumented tier. .NET sends hot R2R code to Tier1Instrumented, which is optimized code with probes. The other path "would produce a lot of new compilations for small methods which were inlined in R2R" and is a "noticeable performance regression from fast R2R to slow instrumented Tier0". | .NET | dotnet F16: dotnet/runtime@0968772 `src/coreclr/vm/tieredcompilation.cpp:262-295`. Instrumenting all Tier0 code took AvaloniaILSpy from 2.03 s to 2.26 s. Instrumented tiers brought it back to 2.03 s (`docs/design/features/DynamicPgo-InstrumentedTiers.md:363-450`). | H33 sends aot-opt to *instrumented T1* (H33:25-35, P05:341). T1 is the Sparkplug-style baseline (P04:53). That is the path .NET rejected. ep9 knew Tier1Instrumented existed (H33:16, P05:332) but never wrote down this reason. Note: ep9 T1 is a template compile (4.2 ns per bytecode, P04:53), so the extra-compile cost may be small. The main cost is slower code while instrumented. | **CONSIDER.** Trigger: K-A4P (H33:94). Add 2 measures and 1 fallback path (LRN-03). |
| 2 | JIT mode needs a hard per-function give-up counter against deopt loops. | Dart (one system) | dart F10: 12 deopts stop inlining. 16 deopts stop optimization for good (dart-lang/sdk@0f1a89e1 `runtime/vm/compiler/jit/compiler.cc:49-53,154-167`, `runtime/vm/compiler/backend/inliner.cc:31-34`). | Per-site exit counters exist (P04:121). Jitless and hybrid have budgets plus PIN (H32:37-43). JIT mode has "no PIN in JIT mode" and no per-function cap (H32:90, H32-Q3). Compile refusals are kept per function (D13:827, route MC-w27-9), but deopt counts are not. | **ADOPT** as text in month 10. Numbers are est. Code comes with T2 (M7). |
| 3 | The tier policy needs a startup phase and a queue limit, not only fixed thresholds. | .NET, HotSpot | dotnet F05/F06: a 100 ms delay that re-arms while startup-like activity goes on. Counting is not stopped when the delay re-arms (`src/coreclr/vm/callcounting.h:55-61`). dotnet F08: an adaptive 1-50 ms compile slice. Bing hit a rejit queue of more than 300,000 methods before the first query (dotnet F17). | 4 | Build the unit compatibility key from one registry, never from a hand-kept list. | Kotlin, Dart, HotSpot | Kotlin's cache flavor string carries a "be sure to update" comment (kotlin F17, JetBrains/kotlin@c2edd73d `kotlin-native/.../NativeSecondStageCompilationConfig.kt:531-616`). | 5 | A unit is a cache. Drop the smallest part that fails, and keep bytecode and facts. | .NET, Leyden | R2R: MAJOR = MINIMUM = 34, "R2R file is a code cache" (dotnet F24). Check_* fixups drop one method; Verify_* fail hard (dotnet F22). Leyden drops only the AOT code on a CPU or GC mismatch and "still uses the other information in the AOT cache" (JEP 544, Consistency; kotlin F34). Seen, not taken: Kotlin partial linkage turns one broken declaration into a run-time throw (kotlin F07). That changes behavior. | Load flow LOAD ERROR / SOURCE / BYTECODE (H35:63-80). The per-function loader fallback is still open for A3 (D13 §9). **REJECT** the partial-linkage throw form: a mismatch never changes JS output. |
| 6 | Cross-unit inlining needs a written "bubble" rule, and later a reverse map (inlinee to inliners). | .NET, Kotlin | R2R InliningInfo2 (v4.1+) and CrossModuleInlineInfo (v6.3+), loaded "only in builds that support profiling, ReJIT, or code versioning" (dotnet F23, corrected). | 7 | A closed world needs a declared "open" interface and a fallback in the same data format. NativeAOT limits (dotnet F29). | Closed-world bundle mode is an open product call due at M7 exit (D13:745). eval is always present (H05:22). PROVEN facts have no guard in any mode (H32:27). | 8 | Every transition needs a force knob and a random/stress knob, run in CI. | .NET, Dart | .NET: debug threshold 2 calls and 1 ms, JitRandomOnStackReplacement, JitRandomGuardedDevirtualization, OSR_LowId/HighId (dotnet F39). Dart: deoptimize_every, deoptimize_alot (dart F06). | ep9 has `--force-tier`, `--force-mode`, the tier matrix and the mode x tier differential (P10:27, :61-62, :172, :267), plus `--feedback-threshold 0` (H16:34). Debugger deopt-all exists (P07:52) but is not a stress knob. | 9 | One IR and one pass list, with the mode passed as data. Count the mode branches, and check invariants at stage boundaries. | Dart, .NET, Kotlin, Roslyn | Dart: 6 AOT-only pass calls, yet 326 / 1,312 mode lines in `runtime/vm` (dart F04, F05). RyuJIT: 49 NativeAOT ABI checks and 13 IsReadyToRun checks (dotnet F02). Kotlin stage validators (kotlin F04, corrected: off unless VERIFY_IR). Roslyn PipelinePhaseValidator (`#if DEBUG`, 6 phases; dotnet F36). | Mode branches are allowed in B1-B3 only (D13:44). P-R1 forbids `cfg` or a mode name in the compilers (D13:246). One CompileRequest/CodeDesc seam (D13:192). | **ALREADY DONE** for the rule. **ADOPT** a branch-count line in the weekly modes check (LRN-08). |
| 10 | The interpreter must be a real tier: same frames, same entry slot, fallback for any function. | .NET, Dart (as warnings) | The new CoreCLR interpreter and tiering "do not work well together currently". It is turned off only by the interpreter knobs, so the integration is partial (dotnet F04). Dart's 2024 interpreter is a terminal tier with its own stack and a setjmp at each call into compiled code (dart F31). .NET 11 iOS runs an interpreter that is always on when dynamic code is off, behind composite R2R (dotnet F03, F32). | One frame layout for T0-T3 and both AOT kinds (H14:22). One slot `{kind, entry}`, no call-site patching (H14:69). Deopt targets the T0 frame at the bytecode offset (H29:28, :33-37). T0 and the compiler are always linked (H05:22). Proven so far only with Spike B stub code (H14:91). | **ALREADY DONE** (design). The real proof comes with T1 (M5). **REJECT** Dart's terminal-tier shape. |
| 11 | Module-init state must not be baked into AOT text. Use two code versions and switch once init is done. | Leyden, Kotlin | JEP 544 compiles a slow version (with class-init checks) and a fast one. "HotSpot uses the slow version initially, and then switches to the fast version once all referenced classes are initialized." It cannot fold static finals (JEP 544, "Differences between AOT code and JIT code"; kotlin F15). Kotlin/Native removes init checks with a whole-program data-flow analysis and made globals lazy (kotlin F15). | Per-run state is never baked (D13:651). | 12 | The sound-type tricks do not carry over to JS: a dispatch table with no holes, an unchecked last devirtualization case, signature shaking, unboxing by declared type. | Dart, Kotlin | The Dart table needs no noSuchMethod holes only because typed calls are sound (dart F17, F20). ## 3. Failures and reversals, mapped to ep9 risks

**Missed by the researcher, found by the verifier (dart):**

1. Exceptions differ by mode. AOT has no deopt metadata: the environments of instructions that can throw become compressed CatchEntryMoves, a list of moves (constant from pool, tagged move, box an untagged value) that the runtime runs to build the catch-entry frame. JIT converts the lazy-deopt environment into CatchEntryMoves when an exception is caught. IL has no exception edges: each CatchBlockEntry acts like a separate function entry with Parameter instructions. Source: runtime/docs/compiler/exceptions.md:6-80
2. Type testing stubs (TTS). AssertAssignable calls a per-type stub that falls back to SubtypeTestCache and then the runtime. In AOT the precompiler guesses which types need a TTS (AttachOptimizedTypeTestingStub) and uses depth-first cid ranges. In JIT a TTS starts as LazySpecializeTypeTest, is rebuilt when more classes load, and is reset after hot reload. Source: runtime/docs/compiler/type_testing_stubs.md:1-85; precompiler.cc DoCompileAll (AttachOptimizedTypeTestingStub)
3. Field unboxing also happens in JIT from declared static types: Field::New calls UnboxFieldIfSupported for non-nullable, non-late instance fields of type double or SIMD. AOT adds TFA-proved int fields. Source: runtime/vm/object.cc:12459-12477; runtime/vm/compiler/runtime_api.cc:1054-1088
4. Checked vs unchecked entry points. TFA's flagSkipCheck in inferred-type metadata lets a call use a function's unchecked entry, which skips covariant parameter checks. Dynamic and switchable calls go through the monomorphic/checked entry. Source: pkg/vm/lib/metadata/inferred_type.dart:21-22; runtime/docs/README.md:771-830 (monomorphic_entry vs normal_entry)
5. Code deduplication and late size passes in the precompiler (ProgramVisitor::Dedup, DiscardCodeObjects, PruneDictionaries) are a third size step after TFA tree shaking and VM-object dropping. The researcher lists them in F16 but not their size role. Source: runtime/vm/compiler/aot/precompiler.cc:449-660, 2932-3020
6. Call-site attributes metadata (vm.call-site-attributes.metadata) comes from the modular call_site_annotator, which runs after TFA in both JIT and AOT builds. It gives receiver static types to the VM, so some static type information reaches JIT too. Source: pkg/vm/lib/modular/metadata/call_site_attributes.dart:22; pkg/vm/lib/kernel_front_end.dart:850-860; kernel_translation_helper.h:1180-1182
7. The pipeline runs OptimisticallySpecializeSmiPhis in both modes, and RangeAnalysis drives bounds-check elimination (with the vm:unsafe:no-bounds-checks phantom mode in AOT). These are mode-shared optimizations not covered in F04/F07. Source: runtime/vm/compiler/compiler_pass.cc:309-326; flow_graph.cc:620-646
8. The graph intrinsic pipeline (RunGraphIntrinsicPipeline) and force-optimized or recognized methods work in both modes without speculation. Source: runtime/vm/compiler/compiler_pass.cc:263-265; runtime/docs/compiler/pragmas_recognized_by_compiler.md
