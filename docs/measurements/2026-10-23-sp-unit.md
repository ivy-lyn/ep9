# SP-Unit: the 11 Spike B opcodes as AOT unit text (M3-P1)

- **What.** `spike-b unit` (`spikes/spike-b/src/unit/`; gate step `bash spikes/spike-b/gate.sh unit`, line `SPIKEB(unit)`). Unit text is placement (b) code (D21-B) plus the unit-data register (H35-Q9). It is built behind the frozen `Emitter` and `Finalize` traits (`spikes/spike-b/src/emit.rs`), in an `ep9_unit` container (header v0).
- **Commit.** Branch `m0m3/p1-sp-unit` on base 2ba3aa4 (M3-P1 SP-UNIT). The orchestrator writes the result row for the gate (M3D-7); this file has the body only.
- **Status.** Structural checks only. No speed claim: no unit bench runs here.

## Design

```text
build (no isolate):  source -> CompiledUnit -> UnitEmitter (Emitter) -> FunctionCode per function
                     -> UnitFinalizer (Finalize) -> ep9_unit bytes:
                        header v0 | text | rodata | rw_template | bytecode | source | unwind

load (per isolate):  ep9_unit::verdict -> LOAD | BYTECODE | SOURCE | LOAD ERROR
  LOAD:  text mapped once per process (file bytes = mapped bytes; 0 relocations)
         unwind registered once (self-test on the first mapped unit's probe)
         RW copy per isolate: ext | links (strong root range) | ics (weak root range) | counters
         cx.unit_data -> directory[64]; directory[slot] = the RW copy
         install_native_b per JS function (its bytecode digest must match)

unit function (AArch64; x86-64 uses r15 / r14 / r13):
  stp x29, x30, [sp, #-48]! ; mov x29, sp ; stp x26, x28, [sp, #16] ; str x27, [sp, #32]
  ldr x27, [x28, #CX_UNIT_DATA] ; ldr x27, [x27, #8*slot]       <- the unit-data register
  [x27 + counter] += 1 ; runtime call: x16 = [[x27 + ext0] + entry] ; blr x16
  call site: if [x27 + ic] == undefined then [x27 + ic] = callee
  exit: ldr x27, [sp, #32] ; ldp x26, x28, [sp, #16] ; ldp x29, x30, [sp], #48 ; br x16
```

- The slot (0-63) is fixed when the unit is built. So the text holds no address and needs no load-time write. A second unit with a used slot gives BYTECODE (check (g)).
- The runtime table is RW external reference 0, not `Cx::runtime_table`. So each isolate can name its own table (check (d) uses a counting table in one isolate only).
- The real `ep9_unit` host gives BYTECODE for every unit with a text section (`DEOPT_META_VERSION` = 0). The spike loads with `spike_host()`, which is the real host with deopt metadata version 1 (`SPIKE_DEOPT_META`). Check (g) shows the real host's outcome.

## Checks (`spike-b unit`, release; `tests/unit.rs` runs each at a smaller n)

| Check | What it shows |
|---|---|
| (a) | Units A (2 JS functions) and B (4) build for AArch64 and x86-64 on any host; two builds give the same bytes. The text scan finds 0 relocations: no 8-byte window is a live address of this process (+/- 64 KiB) or in the code range; on AArch64 also no `adrp`, no `bl`, no `movz`/`movk` address, and no pc-relative form leaves its function |
| (b) | LOAD maps the text once for 3 isolates (default, feedback threshold 0, GC stress + verify + zap); mapped bytes = file bytes; output = T0; counters and the IC cell have the expected values |
| (c) | The unit text itself (a cell reader in the unit) reads every RW word = the copy. Link 0 = `%Object.prototype%` (intrinsic 0); a unit-constant string link survives 3 collections (strong range); a dead callee in an IC cell is cleared by collection 1 (weak range), then the next call fills it again |
| (d) | Thread 1 maps a unit; thread 2 runs it after a barrier handshake and `isb` / `cpuid`. Two isolates, one text, their own RW copies (link 0 differs); isolate 2's runtime-table word names a counting table, and its count = its calls |
| (e) | Two units in one isolate, loaded in both orders: each slot reaches its own copy |
| (f) | The unwind self-test passes on the unit probe; a host backtrace walks through unit frames; an exception crosses a unit frame to a T0 catch; `TerminateHandle` stops a unit loop |
| (g) | 21 mismatch cases end in their S3 outcome (H35-Q7), and the output is still T0's: each native contract version, deopt metadata (real host and own header), target, CPU bit, page size -> BYTECODE; build id, bytecode ABI -> SOURCE; magic, hash, truncation, an intrinsic index that does not exist, an unknown external-reference kind -> LOAD ERROR; slot conflict -> BYTECODE; a changed function -> LOAD with that function on T0. After each LOAD ERROR: no section ran, the isolate has no RW copy of the unit, and `gc()` runs (the loader checks the link records before the unit's script runs, and registers the root ranges only when the link cannot fail) |
