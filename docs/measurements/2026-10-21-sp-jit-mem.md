# SP-JIT-mem, M0 week 3 (2026-10-21): PASS on 4 targets

- Spike: [09-milestones](../plan/09-milestones.md) section 4 row SP-JIT-mem: "One generated function per target. Toggle W^X. Call it, unwind and take a backtrace (DWARF CFI; `RtlAddGrowableFunctionTable`) on all 4 targets". Validates H28 and the `jit` feature of H27.
- Code: `ep9_platform` modules `jit` and `unwind` (features `jit`, `unwind`); spike [`spikes/sp-jit-mem`](../../spikes/sp-jit-mem/README.md) with `gate.sh`.
- Result: **every gate id passes on macOS arm64, Linux x64, Linux arm64 and Windows x64**, on real CI runners, and on x86_64-apple-darwin under Rosetta.

## 1. What the gate does

```text
main -> call_generated -> [outer] -> [inner] -> Rust callback
                          generated code in the code range, unwind data registered
callback: std::backtrace + system-unwinder walk + x19/rbx per frame; or a panic
```

| Check | Pass rule |
|---|---|
| call | both generated functions return the right value |
| icache | 1000 rewrites of an immediate in `inner`; 0 calls run stale code |
| bt-std | `std::backtrace`: callback, inner, outer (exact return addresses), `call_generated`, ..., `main` |
| bt-raw | `ep9_platform::unwind::walk_native_stack` gives both exact return addresses in order |
| callee-saved | the unwinder restores x19/rbx = 0xbeef in the outer frame; `inner` overwrote it |
| panic | a Rust panic in the callback unwinds through both generated frames into `catch_unwind` |
| control | without registration the walk stops at the generated frame (unix). This shows the checks above see the registered data |

## 3. W^X toggle cost

Median of 5 batches. "pair" = open + close a write window, no write. "write+flush" = open, write 4 bytes, close (includes the icache flush). "flush" = icache flush of 16 bytes alone.

| Target | Host | Mode | pair ns | write+flush ns | flush ns |
|---|---|---|---|---|---|
| macOS arm64 | CI macos-15 (arm64 VM) | map-jit (default) | 8.1 | 161 | 141 |
| macOS arm64 | CI macos-15 (arm64 VM) | protect | 1148 | 1411 | 112 |
| macOS arm64 | M5 Max, local | map-jit (default) | 31-34 | 110-123 | 78-92 |
| macOS arm64 | M5 Max, local | protect (`mprotect`, no hardened runtime) | 540-616 | 1460-1990 | 77-91 |
| macOS x86-64 | M5 Max, Rosetta | protect | 798-824 | 1862-1931 | 1-2 |
| Linux arm64 | CI ubuntu-24.04-arm (VM) | protect (default) | 3680 | 3927 | 312 |
| Linux arm64 | CI ubuntu-24.04-arm (VM) | dual-map | 11.5 | 334 | 312 |
| Linux arm64 | OrbStack VM, local | protect | 1055 | 1207 | 95 |
| Linux arm64 | OrbStack VM, local | dual-map | 4.0 | 92 | 92 |
| Linux x64 | CI ubuntu-24.04 (VM) | protect (default) | 3604 | 3615 | 1.4 |
| Linux x64 | CI ubuntu-24.04 (VM) | dual-map | 12.2 | 18.9 | 1.4 |
| Windows x64 | CI windows-2025 (VM) | protect (`VirtualProtect`) | 1392 | 2229 | 8.4 |

- Single thread only. With more threads, `mprotect` and `VirtualProtect` also pay TLB shootdowns.
- The macOS arm64 map-jit pair (8-34 ns) has the same size as [R06] (about 23 ns on an earlier host). It is 2 orders of magnitude below every `mprotect`/`VirtualProtect` pair.
- On arm64 the icache flush costs more than the map-jit toggle pair.

## 4. Platform facts found by the spike

| # | Fact | Evidence | Consequence |
|---|---|---|---|
| F1 | macOS 27: `mmap(MAP_JIT \| MAP_FIXED)` fails with EINVAL | C probe on M5 Max | The code range takes `MAP_JIT` through an address hint; `Cage::reserve_jit` checks the address |
| F2 | macOS 27: after a `MAP_JIT` page is RWX, every `mprotect` of it fails with EACCES (RWX->RX, RWX->NONE). NONE->RWX works once | C probe | The whole code range is mapped RWX at reservation; W^X comes from `pthread_jit_write_protect_np` per thread; release uses `madvise(MADV_FREE_REUSABLE)` |
| F3 | macOS 27: RWX `mmap` without `MAP_JIT` fails (EACCES); RW->RX `mprotect` of a plain page works for a binary without the hardened runtime | C probe | `protect` mode works on macOS arm64 for comparison only. The hardened runtime needs `MAP_JIT` |
| F4 | x86-64 Linux under Rosetta (OrbStack): after a write through the RW view of a dual mapping, the RX view still runs the old code | `icache/dual-map`: stale results | Dual mapping is not coherent under a binary translator. `protect` works there |
| F5 | Linux: libgcc `__register_frame` takes the whole `.eh_frame` section; macOS libunwind takes one FDE per call | gate on both | `EhFrameRegistration` registers per section on glibc, per FDE elsewhere |
| F6 | Windows: `RtlAddGrowableFunctionTable` + UNWIND_INFO in the code memory is enough for `std::backtrace`, `RtlVirtualUnwind` and the SEH unwind of a Rust panic | CI windows-2025 | No `RtlInstallFunctionTableCallback` is needed |
| F7 | Windows: an unregistered x64 frame looks like a leaf to `RtlVirtualUnwind`; a walk then reads a return address from the shadow space | x64 unwind rules | Every generated frame must be registered before it runs on Windows. The spike skips the negative control there |

## 6. Reproduce

```sh
bash spikes/sp-jit-mem/gate.sh                       # host gate (+ Rosetta and Windows build on macOS arm64)
cargo test -p ep9_platform                           # the jit and unwind unit tests build under cfg(test)
cargo run --release --manifest-path spikes/sp-jit-mem/Cargo.toml -- --iters 100000
```

Linux in Docker (from a copy of the repo, so that the root `Cargo.lock` stays untouched):

```sh
docker run --rm --platform linux/arm64 -v "$PWD":/src -w /src rust:1.99.1-slim-bookworm bash spikes/sp-jit-mem/gate.sh
```
