**Estimate per year (est.).** oxc published a release about once a week (0.154.0 on 2026-10-13, 0.155.0 on 10-19, 0.156.0 on 10-27, 0.157.0 on 11-02). One bump for each 2 releases is about 26 bumps a year. At 0.59 agent-hours each, that is about 15 agent-hours a year, far below 1 PM (about 160 hours). Limits of this reading: it is one bump, and it needed no API change; a release that changes the AST or the `Semantic` API costs more. The gate reads the bumps up to M2 exit.

**What the bump changed in behaviour (all toward the spec or node):**

- **rx-dupnames** (IN #29): oxc 0.155.0 accepted 5 regex literals in which two groups of one name can both take part (MightBothParticipate); oxc 0.157.0 rejects them, as node v26.13.0 does. So no ep9-side check in `regex_check.rs` is needed, and the P1 patch count stays 0 of 3.
- **PRE-1** (the strict `eval` / `arguments` assign error on a name that is only read): oxc_semantic 0.157.0 reports it only for writes. The ep9 post-filter (`crates/ep9_frontend/src/strict_filter.rs`) stays as a guard; on its test cases it finds nothing to drop.
- **Not fixed upstream:** the oxc lexer debug assert after a fatal error (`lexer/mod.rs:328`, fuzz run 41579263254) still fails with tokens on in 0.157.0, so `regex_check::parse` keeps its debug-only first pass.
