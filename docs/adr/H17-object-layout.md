## Context

- A monomorphic property load must be one shape guard and one load (02 §6 H17). So the shape must say where each field is, and the object must not need a second lookup.
- Depends on H8 (word0, ShapeId = offset in the shape space), H9/H11 (barrier v2 for word0), H18 (elements), H19 (atom keys). H16 (ICs) and the JIT/AOT tiers depend on it.

## Decision

v0 (M0 wk4) builds the plan's JSObject header with shapes in the shape space. The plan items marked "decide before M1a" below are not built.

```text
 +0  word0   shape_id u32 | gc_state | kind | flags u16 (bits 0-7 in-object slot count, bit 8 is-prototype)
 +8  SLOTS (fast, out-of-object fields) | PROPS (dictionary table) | undefined
 +16 ELEMENTS | undefined
 +24 fixed fields of the kind, then in-object slots [capacity]

 shape (64 B, Space::Shape):  +8 proto  +16 parent  +24 descriptors  +32 transitions
                              +40 transition table | PROTO_INFO (unique)  +48 counts  +56 flags
```

These are the whole month-4 kind list (plan v9 rule 18): construct sites and instanceof caches are IC_HANDLER cells with new handler kinds (IC_LAYOUT 2, H16), and a literal site keeps only its feedback slot halves. M4-P0 registers none of these kinds; the role that first allocates one registers its trace function (`tests::layout4::every_month_4_kind_is_registered`, since M4-P4).

Every word after word0 is a Value (a native pointer uses the native-word encoding), so each new kind has one trace function over its whole size. The exotic internal methods of ARGUMENTS and MODULE_NAMESPACE are routed from `exotic.rs` and the `property.rs` set, define, delete, own-keys, array-index and for-in paths to `arguments.rs` and `module.rs` (one kind test per hook); a routed object on a prototype chain decides the `[[Set]]` walk through its own `[[Set]]` (§10.1.9.2 step 1.b), and the `[[Get]]` and `[[GetOwnProperty]]` hooks may throw (a namespace binding in its TDZ). The M3-P0 stubs take the ordinary path.

### Accessors (M0 wk4, P3-ACC)

JSC style (plan §2 row 6): an accessor is an attribute bit plus an immutable pair cell in the
ordinary value slot, so a shape describes an accessor exactly as it describes a data field.

```text
 descriptor details: attrs = ACCESSOR | e | c (never WRITABLE), field i
 field i (in-object, SLOTS or PROPS entry) ──> ACCESSOR_PAIR (kind 67, 24 B): +8 getter, +16 setter
                                               (a callable, or undefined when absent)
```

## Consequences

- **Gains.** A shape guard is one u32 compare, and the field offset comes from the shape. `shape_of` needs no runtime pointer, so host paths (`proto_of`, `is_extensible`) stay free functions.
- **Costs.** The 64 GiB cage alignment leaves 2,048 cage slots below 2^47. Prototype objects never share shapes. Class constructors with `extends` go to dictionary mode (SetPrototypeOf with own properties).
- **Follow-ups.** P3-IC built the (shape, field) caches (H16 K9-K18). Exotic own properties (array `length` and elements, a constructor's lazy `prototype`, String wrapper properties) are not in shapes: the validity cells cover an element that appears or goes away (an element add or delete on a prototype is a structural change, `shape::note_change`, which clears that prototype's VALIDITY_CELL and the cells below it; M4-P1, H16 K5), but a holder's exotic property is never a field load. P3-ACC built accessors (section above); the super paths pass the receiver (`LoadKeyedFromSuper`, `StoreToSuper`; opcode 0x22 with P3-IC). An IC must not make a data handler for an `ACCESSOR` descriptor: the slot holds the pair. Slack tracking replaces the fixed `new F` capacity of 8.

| Slack tracking | V8 style, per root shape of a prototype (the PROTO_INFO root shape that `new F` instances start from; V9-D8 keeps the initial shape in the Construct site's Call slot). The first N instances (N = 7, est.; V8 starts its counter at 7, external) get a generous capacity: 8, or the count of `this.<name> =` stores in the constructor's bytecode + 8, at most 255 (word0 flags bits 0-7). A field added after the constructor goes out of line, as a ninth field did. The count is a size hint, never a correctness input. The capacity is chosen at F's first construct, from F's code and the prototype F has then, and F's FunctionInfo keeps it (`slack_capacity`, one byte, no Value), so a later construct runs no scan (a scan at each cold construct cost about 8,300 instructions) and a prototype that gains a data field later changes no capacity (M5-P2 integration fixer; it replaced a per-thread cache keyed by a hash of the code bytes, which could hand one function another function's constant indices). Why not the tracker: a construct site that switched to a final root after N cold constructs (built and measured in M5-P2) made two root shape families per constructor, and the T0 ICs saw both: richards +12.7%, deltablue +9.0%, raytrace +2.4%, splay +1.5% instructions, earley-boyer only -2.8% (mac a64, `EP9_HASH_SEED=1`). The root shape `flags` bits 4-7 (`shape::flag::SLACK_SHIFT`, OBJECT_LAYOUT 5) are not used: no counter is needed. It reads no execution policy (rule 40; `tests::slack` checks equal capacities with and without feedback vectors) |
| Representation and const bits | Per field descriptor: a representation {none, int32, double, heap object, any}, one-way (none -> int32 -> double -> any; none -> heap object -> any), and a const bit that a second store after the first initializing store clears. A Value already holds a double unboxed (H6), so double needs no box; the representation is a fact for field loads (H30), not a storage form. A generalization or a const clear changes the descriptor in place and pops the field's fuse. The constness bit and the replacement watchpoints register as InvalidatingFuses named by a Dynamic FuseRef descriptor (H31-Q1), read through a LinkSlot; no code assumes a fuse-word address. Built in month 5 (CONST/REP), on the H31 registry v0. **As built (2026-10-29, M5-P2 CONSTREP; C-02):** details bits 4-6 hold the representation (`shape::rep`: NONE 0, INT32 1, DOUBLE 2, HEAP 3 = no number (a cell, undefined, null, a boolean), ANY 4; join: NONE gives the other, INT32 and DOUBLE give DOUBLE, else ANY), bit 7 the const bit. The first store of a field is its add (`props::own_add`): the new descriptor gets the value's representation and const; an add along a transition that other objects took widens the field to the value and keeps const. Every later store (`props::field_set`) is a second store: it widens and clears const for the whole family, so const means no object of the family replaced the value (V8's const field). A family is the owner shape that added the field (`shape::field_owner`) and its live descendants; a branch holds a copy of the entry, and a widening writes every copy in place (`shape::set_field_bits_in_family`); a prototype-mode object leaves its tree family with its own copy of the cell (`shape::proto_info_for` gives the new unique shape a copy of a tree shape's DESCRIPTORS, `shape::own_descriptors`; M5-P2 integration fixer), so no cell is shared between families and a widening never writes a cell that the family's owner, and so its kind-3 fuse, does not read. An elements-kind transition joins the old shape's field bits into the new one (`shape::with_elements_kind`). A shape made with no value known (`shape::add`: the cached function shapes) holds ANY, not const. A widening pops the field's Dynamic fuse, descriptor kind 3 "field constness and representation" (H31 As built (9)).
