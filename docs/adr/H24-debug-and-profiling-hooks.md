## Context

- The inspector (CDP Debugger and Runtime) and the sampling profiler must work in every mode (JIT, AOT-jitless, hybrid) with no redesign (G5, 07 §2).
- A debugger can change a binding that compiled code treats as a fact. In node, a session rewrote strict `let` and `const` locals (B28, B28c) and retyped a field inside a call-free loop [R18]. So PROVEN facts stay sound only if every such write goes through a fuse or a T0 frame.
- Depends on: H14 (canonical frame, pc→code registry), H31 (InspectorSession and DebuggerBindingWrite fuses), H29 (deopt), H35 (unit maps). Depended on by: H30 (fact provenance), H32 (guard policy).

## Decision

Copied from the plan row: lazy position tables, kept ScopeInfo, a debug bytecode copy, frame pointers everywhere, perf jitdump. Session connect pops the InspectorSession fuse (H31): deopt all, AOT frames lazily. While a session is connected, T2 and AOT code treat every interrupt poll as a heap effect point. A debugger write to a local or parameter succeeds only on a T0 frame; on a JIT or AOT frame it returns a protocol error. Breakpoints and `debugger` statements deopt to T0 before the pause. A write to a context, module or script binding first pops the DebuggerBindingWrite fuse (H31). BytecodeGen never folds bindings. Units carry pc→bytecode and position maps and a perf map (02 §6). [2026-11-03, M6-P1 B3T1; FREEZE-M1 B3, doc 13 C-22 (3) and T10, clarify:] Per code kind. JIT code depends on InspectorSession as an InvalidatingFuse: a connect invalidates it, and its frames deopt lazily. AOT code reads InspectorSession as a GuardFuse at its polls: it stays Active (a fuse pop is one-way, H31, so an invalidation would send a jitless isolate to T0 for good), and its frames on the stack at connect deopt lazily. So "deopt all" names the JIT code, and "AOT frames lazily" the AOT frames on the stack.

## Consequences

- **Gains.** Error.stack, the unwinder, breakpoints and later deopt read one slot per frame, in every tier. A sampler can walk VM frames from a suspended thread. PROVEN facts need no guard against debugger writes.
- **Costs.** JIT and AOT code pay one store per runtime call and poll (R2), and keep a frame pointer. A debugger cannot change a local of a JIT or AOT frame without a deopt.
- **Follow-ups.** H31 fuses (M1). The inspector (M4). The sampler (M6). Perf map and jitdump (H24-Q2).
