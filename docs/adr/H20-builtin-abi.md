## Context

- The most-copied code shape: thousands of builtins. A change after the freeze touches all of them [R07: Brimstone's handle refactor].
- Depends on: H10 (CSS keeps Rust locals alive), H14 (frame layout: `Args` reads the host frame), H06 (`Value` wraps `NonZeroU64`), H19 (atoms are the property keys), H22 (realms, R5). Depended on by: the builtins (P2, P3), H13 (BuiltinId index list), H35 (unit link cells), the JIT and AOT host-call stub.

## Decision

Plan row: `fn(cx, this, args, new_target) -> JsResult<Value>`. `Args` is a frame view; `Throw` is a ZST; no `&mut` to a heap object across a JS call. AOT code reaches builtins through the isolate table or the link table (02 §6). The v1 draft keeps this shape with `Local` for `Value` (a rewrite of the row's result type before the freeze; P4-DOCS updates 02):

```rust
pub type HostFn = for<'s> fn(&mut Cx<'s>, Local<'s>, Args<'s>, Local<'s>) -> JsResult<Local<'s>>;
//                           cx           this       args (= fp)  new_target
```

Conversions: `to_boolean`, `to_number`, `to_integer_or_infinity`, `to_int32`, `to_uint32`, `to_length`, `to_string`, `to_property_key`, `to_object`, `to_primitive`, `same_value`, `is_strictly_equal`. Spec helpers: `to/from_property_descriptor`, `create_list_from_array_like` (into an `ArgsBuilder`), `get_prototype_from_constructor`, `ordinary_create_from_constructor` (a `prototype` that is not an object falls back to the default intrinsic of GetFunctionRealm(constructor), §10.1.14 step 4). Creation: `new_object(_with_proto)`, `new_array`, `create_array_from_list`, `new_string(_utf16)`, `new_wrapper`, `new_symbol`, `intrinsic(IntrinsicId)`. P3 surface (P2-BTAB): `symbol_for`, `key_for`, `symbol_description`, `descriptive_string`, `this_primitive_value(v, PrimitiveType)`, `set_function_name`, `set_function_length`, `new_bound_function(target, this, args.rest(i))`, `has_intrinsic`, `initial_name(f) -> Option<Local<JsString>>` (the `[[InitialName]]` of a host function, from its FunctionInfo; `None` for bytecode and bound functions; an accessor's functions are named "get x" / "set x"; W4-P3FIX-INITIAL-NAME). Calls: `call`, `call_args(f, this, args.rest(i))`, `call_built`, `construct(f, args, new_target)` with any constructor as new.target, `construct_args`, `construct_built`. **Index access** (ABI-1, `crates/ep9_vm/src/abi/index.rs`): `get_index(o, k)`, `has_index(o, k)`, `set_index(o, k, v, throw)` and `delete_index(o, k, throw)` are Get, HasProperty, Set and `[[Delete]]` / DeletePropertyOrThrow with the key `! ToString(𝔽(k))` for a `u64` `k`. A dense element and a missing index need no key, so they make no atom; a stored integer key of an object with at most 64 own properties is found by a scan (the array index from the atom's hash field, or the digits); otherwise the key is interned and the ordinary path runs (`property::get_index` and its neighbours, `crates/ep9_vm/src/property.rs:1423`). A missing array index stops at the receiver while no prototype has an index key (`shape::proto_index_keys`). `poll_interrupt()` takes one interrupt budget unit and polls when it runs out (termination gives an uncatchable `Err(Throw)`): a builtin loop over indices has no back edge, so it calls it once per index. **Iterator protocol** (ABI-3, `crates/ep9_vm/src/abi/iter.rs`): `get_iterator(obj)` (GetIterator, sync; the async form comes later as an addition), `get_iterator_from_method(obj, method)`, `iterator_step_value(&mut record) -> Option<Local>` (a throw or done sets `[[Done]]`; one interrupt budget unit per step) and `iterator_close(&record, completion)` (a throw completion keeps its exception whatever `return` does). Accessor properties are built (P3-ACC). v0 limits: these throw "not implemented" until H18 element storage: an accessor on an array index, an array element whose attributes are not {w, e, c}, and a non-writable array `length` (W4-ACC-ELEM).

**Internal slots** (ABI-SLOTS, `crates/ep9_vm/src/abi/slots.rs`): `new_object_with_slots(proto, class, n)`, `slot(o, class, i)`, `set_slot(o, class, i, v)` and `object_class(v)`. The class decides what each slot index means, and its builtin module names the indices. Slots hold Values in a heap cell (plan rule 8), and property code never touches them. A slot index past the count panics.

**JIT and AOT** never call a `HostFn` (Rust ABI). They call one `extern "C"` host-call stub `(cx, fp) -> bits` that pushes the host frame and runs `call::call_host`; the builtin is named by its FunctionInfo or its `BuiltinId` (block 7 bits + index 9 bits) through the isolate table or a unit link cell (H35).

### Builtin tables (M0 wk4 P2)

```text
IsolateConfig { builtins: Some(&ep9_builtins::TABLE), .. }
Isolate::new
  builtins::check      both tables pass check_tables (cached per table)  -> IsolateError::BuiltinTable
  Runtime::new
  builtins::prepare    one dense FunctionInfo array + one root range of function slots per module
  realm::init          atoms; core intrinsics: %Object.prototype%, %Function.prototype% (VM builtin 0.0),
                       Array/String/Number/Boolean/Iterator/ArrayIterator/Error prototypes, the global
  builtins::install    VM table (block 0), then the embedder table, modules in order:
                       pass 1 every function object; pass 2 the intrinsics; pass 3 the properties
```

`check_tables` rejects: a block ≥ 128 or used twice; more than 512 definitions; an intrinsic made twice, or a core one made other than as a VM builtin; a property on, or a reference to, an intrinsic nothing makes; a definition index out of range or of the wrong kind (`Builtin` needs a Method or Constructor, `Accessor` a Getter/Setter); an `Alias` of a key not defined earlier on the same object; a key defined twice on one object. A constructor that a table makes must get `prototype` ({} attributes) as its first table key, and must get one (W4-BTAB-CTOR-PROTO-FIRST). Install also refuses, in every build, a key the target already has (a function's own `length`/`name`, or anything realm init made), with `IsolateError::BuiltinTable` (W4-BTAB-INSTALL-NO-SECOND-KEY). Install errors (a well-known symbol or an accessor that does not exist yet) fail `Isolate::new` with a message naming the module and key.

**One function object per builtin and realm.** `builtins::function_object` makes it on first use and keeps it in the module's root slot (the first realm) or in the install list while a later realm installs (`builtins::begin_realm_install`), so an `Alias`, an intrinsic and a property name one object in each realm. Every realm's function object of a definition shares its FunctionInfo. The FunctionInfos sit in one boxed slice per module (no Box per function); `rt.infos` keeps only embedder host functions.

**Ids are golden-checked.** `crates/ep9_vm/tests/golden/vm-builtin-ids.txt` (the VM module plus the `IntrinsicId` list) and `crates/ep9_builtins/tests/golden/ids-<module>.txt` hold one line per definition; a reorder fails them, and `EP9_BLESS=1` rewrites them after a review that sees only appended lines.

**The VM table** (`crates/ep9_vm/src/natives.rs:570`, block 0): `%Function.prototype%` (a function that returns undefined, §20.2.3), `Function` (CreateDynamicFunction, §20.2.1.1, through the compiler hook `compile_function`, `crates/ep9_vm/src/abi/script.rs`; an EvalError on an isolate without hooks), `Object` (new.target, then `to_object`, §20.1.1.1), `Array`, the 7 error constructors, `Object.prototype.toString`/`valueOf`, `Array.prototype.join`/`toString`/`push` (`push` is generic: a non-Array `this` takes the spec steps, §23.1.3.23), `Array.prototype.values` (also `Array.prototype[@@iterator]`, one function object), `Array.prototype.keys`/`entries` (VM ids 0.28, 0.29; M2-P4 B-ARRAY), `%ArrayIteratorPrototype%.next`, `String.prototype[@@iterator]`, `%StringIteratorPrototype%` with its `next` and `@@toStringTag` "String Iterator", `%Iterator.prototype%[@@iterator]`, the `%Iterator.prototype%[@@toStringTag]` accessor (get "Iterator", set SetterThatIgnoresPrototypeProperties; VM ids 0.31, 0.32), `Function.prototype[@@hasInstance]` (OrdinaryHasInstance; VM id 0.30), the `%Array.prototype%[@@unscopables]` object (`IntrinsicId` 44) (all three M2-P5 VM-SMALL), `Error.prototype.toString`, `%GeneratorFunction%` (through the compiler hook like `Function`), the `%GeneratorPrototype%` methods `next`, `return` and `throw`, `%AsyncFunction%` (a not-implemented stub until month 3), the global `eval` (`%eval%`, indirect eval, §19.2.1; direct eval is `crates/ep9_vm/src/interp/slow/eval.rs`), and the globals `globalThis`, `undefined`, `NaN`, `Infinity`.

**Crate layout.** `ep9_builtins` (engine dependencies ep9_vm and ep9_math only, `#![forbid(unsafe_code)]`) has one file per module, each with `BLOCK`, `DEFS`, `INTRINSICS`, `PROPS` and `MODULE`: object 1, function 2, array 3, number 4, boolean 5, string 6, symbol 7, math 8, global 9. `TABLE` lists them in that order, which is the property order. Its `clippy.toml` repeats the root bans (clippy reads only the nearest file) and adds `disallowed-types`: `ep9_value::Value`, `Unpacked`, `Word0` and the ep9_heap cell types (re-exports such as `ep9_vm::Value` resolve to them). `TEMPLATES.md` is the writing guide, and its code blocks are doctests. `ep9_cli` and `tools/test262` pass `TABLE`; test262 `exec` exits 2 when an isolate has no table.

**Embedders get `Local` too** (H20-Q4): `Isolate::with_cx(|cx| ...)` runs a closure with a `Cx`; the `for<'s>` bound keeps every `Local` inside it (a `compile_fail` doctest proves the escape does not compile). The scoped forms of the old `Value` API are `Cx` methods (M0 month 2 P3, C11; `crates/ep9_vm/src/isolate.rs:670`): `run_script(unit, file) -> JsResult<Local>` (loads and runs a unit as `Isolate::run_script`), `global_binding(name) -> JsResult<Option<Local>>` (GetBindingValue of the global environment: the lexical record first, a binding in its TDZ throws a ReferenceError, then HasProperty and `[[Get]]` on the global object, so a getter runs; `None` = unresolvable) and `display(v) -> String` (runs no JS). The scoped call is the existing `call`, and `global()` keeps its signature. `evaluate_script(source, file) -> JsResult<Local>` (M0 month 2 P3-EVAL-VM, `crates/ep9_vm/src/abi/script.rs:65`) compiles a source string as a sloppy Script through the compiler hook `compile_script` and runs it as `run_script` does (`this` = the global object; an EvalError on an isolate without hooks). A `compile_fail` doctest per new form shows that its `Local` cannot leave `with_cx`. `Isolate::global` (no JS) gives `None` for a binding in its TDZ.

## Consequences

- **Gains.** A `Local` costs nothing (no handle scope); a host call passes 4 integer words (cx, this, args, new_target), which fits the 4 Win64 argument registers, and returns in one register. Builtins reach the VM only through `Cx`, so `forbid(unsafe_code)` holds in `ep9_builtins`. No `Vec<Local>` is ever needed: lists are a `ScratchList`, a JS array or an `ArgsBuilder`.
- **Costs.** Every builtin spells `<'s>`. R2 is a lint plus a debug check, not a type error. `call`/`apply` copy the arguments once (H20-Q3). The LIFO checks run at run time.
- **Costs of the tables.** A block holds at most 512 builtins, and 128 blocks exist; an id never moves, so a removed builtin keeps its slot. A table error shows at `Isolate::new`, not at compile time (the checks are cached per table).
- **Follow-ups.** Done in M0 wk4: gc-lint and the debug check (P2-LINT); the symbol entry points and `%Symbol.prototype%` (P2-SYM merge); accessors in `define_own_property` and `PropValue::Accessor` installs (P3-ACC); the builtins of `TEMPLATES.md` 1-10 and the `@@iterator` protocol (P3-BLTA, P3-BLTB, P3-NAT). Done in M0 month 2 P1: index access (ABI-1) and the iterator protocol (ABI-3). Open: H18 element storage for the v0 limits above; H22 realms for R5; the async GetIterator and GetMethod with a well-known symbol (additions for the builtins that need them). Freeze at M0 exit.
