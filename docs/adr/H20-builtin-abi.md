## Context

- The most-copied code shape: thousands of builtins. A change after the freeze touches all of them [R07: Brimstone's handle refactor].
- Depends on: H10 (CSS keeps Rust locals alive), H14 (frame layout: `Args` reads the host frame), H06 (`Value` wraps `NonZeroU64`), H19 (atoms are the property keys), H22 (realms, R5). Depended on by: the builtins (P2, P3), H13 (BuiltinId index list), H35 (unit link cells), the JIT and AOT host-call stub.

## Decision

Plan row (02 §6): `fn(cx, this, args, new_target) -> JsResult<Local<'s>>`. `Args` is a frame view; `Throw` is a ZST; no `&mut` to a heap object across a JS call. AOT code reaches builtins through the isolate table or the link table. The row said `-> JsResult<Value>` until the v1 draft put `Local` in place of `Value` (a rewrite of the row's result type before the freeze; P4-DOCS updated 02 in 6bebbb1, M0 wk4):

```rust
pub type HostFn = for<'s> fn(&mut Cx<'s>, Local<'s>, Args<'s>, Local<'s>) -> JsResult<Local<'s>>;
//                           cx           this       args (= fp)  new_target
```

Calls: `call`, `call_args(f, this, args.rest(i))`, `call_built`, `construct(f, args, new_target)` with any constructor as new.target, `construct_args`, `construct_built`. **Index access** (ABI-1, `crates/ep9_vm/src/abi/index.rs`): `get_index(o, k)`, `has_index(o, k)`, `set_index(o, k, v, throw)` and `delete_index(o, k, throw)` are Get, HasProperty, Set and `[[Delete]]` / DeletePropertyOrThrow with the key `! ToString(𝔽(k))` for a `u64` `k`. A dense element and a missing index need no key, so they make no atom; a stored integer key of an object with at most 64 own properties is found by a scan (the array index from the atom's hash field, or the digits); otherwise the key is interned and the ordinary path runs (`property::get_index` and its neighbours, `crates/ep9_vm/src/property.rs:1423`). A missing array index stops at the receiver while no prototype has an index key (`shape::proto_index_keys`). `poll_interrupt()` takes one interrupt budget unit and polls when it runs out (termination gives an uncatchable `Err(Throw)`): a builtin loop over indices has no back edge, so it calls it once per index. **Iterator protocol** (ABI-3, `crates/ep9_vm/src/abi/iter.rs`): `get_iterator(obj)` (GetIterator, sync; the async form comes later as an addition), `get_iterator_from_method(obj, method)`, `iterator_step_value(&mut record) -> Option<Local>` (a throw or done sets `[[Done]]`; one interrupt budget unit per step) and `iterator_close(&record, completion)` (a throw completion keeps its exception whatever `return` does). Accessor properties are built (P3-ACC). v0 limits: these throw "not implemented" until H18 element storage: an accessor on an array index, an array element whose attributes are not {w, e, c}, and a non-writable array `length` (W4-ACC-ELEM).

**Internal slots** (ABI-SLOTS, `crates/ep9_vm/src/abi/slots.rs`): `new_object_with_slots(proto, class, n)`, `slot(o, class, i)`, `set_slot(o, class, i, v)` and `object_class(v)`. The class decides what each slot index means, and its builtin module names the indices. Slots hold Values in a heap cell (plan rule 8), and property code never touches them. A slot index past the count panics.

**JIT and AOT** never call a `HostFn` (Rust ABI). They call one `extern "C"` host-call stub `(cx, fp) -> bits` that pushes the host frame and runs `call::call_host`; the builtin is named by its FunctionInfo or its `BuiltinId` (block 7 bits + index 9 bits) through the isolate table or a unit link cell (H35).

### Builtin tables (M0 wk4 P2)

```text
IsolateConfig { builtins: Some(&ep9_builtins::TABLE), .. }
Isolate::new
  builtins::check      both tables pass check_tables (cached per table)  -> IsolateError::BuiltinTable
  Runtime::new
  builtins::prepare    one dense FunctionInfo array + one root range of function slots per module
  realm::init          atoms; core intrinsics: %Object.prototype%, %Function.prototype% (VM builtin 0.0),
```

`check_tables` rejects: a block ≥ 128 or used twice; more than 512 definitions; an intrinsic made twice, or a core one made other than as a VM builtin; a property on, or a reference to, an intrinsic nothing makes; a definition index out of range or of the wrong kind (`Builtin` needs a Method or Constructor, `Accessor` a Getter/Setter); an `Alias` of a key not defined earlier on the same object; a key defined twice on one object. A constructor that a table makes must get `prototype` ({} attributes) as its first table key, and must get one (W4-BTAB-CTOR-PROTO-FIRST). Install also refuses, in every build, a key the target already has (a function's own `length`/`name`, or anything realm init made), with `IsolateError::BuiltinTable` (W4-BTAB-INSTALL-NO-SECOND-KEY). Install errors (a well-known symbol or an accessor that does not exist yet) fail `Isolate::new` with a message naming the module and key.

**One function object per builtin and realm.** `builtins::function_object` makes it on first use and keeps it in the module's root slot (the first realm) or in the install list while a later realm installs (`builtins::begin_realm_install`), so an `Alias`, an intrinsic and a property name one object in each realm. Every realm's function object of a definition shares its FunctionInfo. The FunctionInfos sit in one boxed slice per module (no Box per function); `rt.infos` keeps only embedder host functions.

One test: an entry point is an `Isolate` method that runs ABI code (a `Cx` scope, JS or a `HostFn`), or that takes a hook, a function of the embedder that is called while ABI code runs. The 8 entry points are `with_cx`, `with_cx_checkpoint`, `create_realm`, `perform_microtask_checkpoint`, `take_unhandled_rejections` (the message of a reason that is an object but not an Error is ToString(reason), which can call JS or a `HostFn`; its doctest shows a `HostFn` `toString` that runs in the call), `new` (`IsolateConfig` gives it 3 kinds of hooks: the builtin tables, whose `HostFn`s ABI code calls; the `PromiseRejectionTracker`; and the `CompilerHooks`, which `Cx::evaluate_script` (`abi/script.rs`), `eval` and `Function()` call), `register_host_function` (it takes a `HostFn`) and `with_module_host` (it takes the `resolve` and `load` hooks that `import()` calls; like the compiler hooks, they get no `Cx`). ## Consequences

- **Gains.** A `Local` costs nothing (no handle scope); a host call passes 4 integer words (cx, this, args, new_target), which fits the 4 Win64 argument registers, and returns in one register. Builtins reach the VM only through `Cx`, so `forbid(unsafe_code)` holds in `ep9_builtins`. No `Vec<Local>` is ever needed: lists are a `ScratchList`, a JS array or an `ArgsBuilder`.
- **Costs.** Every builtin spells `<'s>`. R2 is a lint plus a debug check, not a type error. `call`/`apply` copy the arguments once (H20-Q3). The LIFO checks run at run time.
- **Costs of the tables.** A block holds at most 512 builtins, and 128 blocks exist; an id never moves, so a removed builtin keeps its slot. A table error shows at `Isolate::new`, not at compile time (the checks are cached per table).
- **Follow-ups.** Done in M0 wk4: gc-lint and the debug check (P2-LINT); the symbol entry points and `%Symbol.prototype%` (P2-SYM merge); accessors in `define_own_property` and `PropValue::Accessor` installs (P3-ACC); the builtins of `TEMPLATES.md` 1-10 and the `@@iterator` protocol (P3-BLTA, P3-BLTB, P3-NAT). Done in M0 month 2 P1: index access (ABI-1) and the iterator protocol (ABI-3). Done in M0 month 3 P1: H22 realms for R5 (REALMS). Done in M0 month 3 P3: the Freeze table, the public paths (with `CollectionCursor`), the two-realm R5 test and the core golden (FREEZE-PREP); the raw `Value` forms of `Isolate` removed (EMBED-MIGRATE) and H20-Q4 filled. Open: H18 element storage for the v0 limits above; the async GetIterator and GetMethod with a well-known symbol (part-2 additions for the builtins that need them). The core freezes at M0 exit (Freeze table).
