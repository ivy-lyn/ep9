# ep9 plan: GC design and stages

- ep9 uses a hybrid **like JSC**, not like V8: generations through sticky mark bits, concurrent retreating-wavefront marking (JSC Riptide, not SATB), and no object moves at first [R05][R09].
- Dual mode adds no GC algorithm. Unit text holds no heap address, so the GC never patches AOT code [R14][R17].
- Roots: a conservative scan of native stacks (Rust, JIT and AOT frames), and a precise scan of everything else, now including unit RW data.
- One store barrier fast path runs in T0, T1, T2, T3, baseline-AOT and optimized-AOT code. It checks first; when it fires, the slow path does the store. A unit with another barrier version falls back to its bytecode [R11].
- Stages S0-S4 and their gates stay as in plan v1. The S2b verifiers V2 and V3 also run under forced AOT modes by M8 exit.

IDs used here: H6, H7, H8, H10, H11, H12, H13, H14, H21, H22, H29, H32, H35; D6, D14, D21; G7; N9; S0, S1, S2a, S2b, S3, S4; M0-M8; A1, A2, A3, A4; T0-T3; baseline-AOT, optimized-AOT; K-A4J, K-A4P; E1-E3 (barrier elision); V1-V3 (barrier verifiers); RK3, RK4, RK10, RK12, RK35.

## 1. Answer to "hybrid like V8?"

ep9 uses a hybrid **like JSC**. It is generational and concurrent, but it does not move objects at first. It does not start with V8's semi-space copying.

| V8 piece | V8 status (main, 2026-10-20) | ep9 choice | Why |
|---|---|---|---|
| Young generation | Semi-space Scavenger (copying). MinorMS and sticky mark bits are experimental and off [R05] | Sticky mark bits, non-moving (S1) | Objects never move under live Rust pointers. In Rust that is the worst soundness risk [R05] |
| Old generation | Concurrent marking (Dijkstra barrier) plus compaction | Concurrent retreating-wavefront marking (S2) plus opportunistic evacuation (S3) | One barrier serves S1 and S2 (JSC Riptide). Termination rescans the one stack per isolate; CSS makes that cheap [R05] |
| Stack roots | Precise handles. CSS is experimental. The direct-handle migration takes years [R05][R09] | CSS of native stacks; precise heap | rustc cannot emit stack maps [R05] |
| Pointers | 32-bit compressed in a 4 GB cage (Chrome, d8). node 24.22 has no compression | 64-bit NaN-box in a cage below 2^47 (H6, H7) | No decode. Doubles unboxed. G7 caps the memory cost against both builds [R06] |
| Production precedent | n/a | JSC, Oilpan and LibJS (97.72% test262) ship stack-only CSS over a precise heap [R09] | Proven model |

**What dual mode changes.** Nothing in the algorithms. It adds three rules:
- Unit text holds no heap address (H12, H35). It reaches heap objects only through root indices, intrinsic indices or RW cells (H13).
- So S3 evacuation never patches unit text. The precise visitor updates RW cells, as it updates FeedbackVector slots.
- AOT code bakes in the barrier, as JIT code does. HotSpot Leyden rejects AOT code when the GC barriers differ [R11]. ep9 checks a barrier version (§3).

**MMTk is not the v1 core** [R05][R09].
- It has no Windows support (#961).
- Its V8 binding runs only NoGC.
- It has no generational + concurrent plan outside OpenJDK.

ep9 keeps its contract MMTk-compatible: side bits, size from header, slot visitors, pinning, VO lookup. MMTk can then serve as an A/B backend on Linux and macOS.

## 2. Roots

```
native stack: Rust + JIT + AOT frames ------------> CONSERVATIVE
    naked trampoline spills callee-saved registers first
      aarch64: x19-x28, fp, lr, d8-d15 | SysV x64: rbx, rbp, r12-r15 | Win64: + rsi, rdi, xmm6-xmm15
    -> scan each word -> cage range check -> VO bitmap (interior pointers allowed) -> pin for this GC
VM stack: register files (T0; others per D21) ----> PRECISE (every slot is a valid Value; undefined on push)
Global<T> table (embedder, runtime) --------------> PRECISE
ScratchRoots (Rust temporary lists) --------------> PRECISE, scoped
heap objects -------------------------------------> PRECISE (visitor chosen by the header kind byte)
unit RW data (NEW; one copy per isolate, H22) ----> PRECISE, range registered by the ep9_unit loader
    link cells .................................... strong
    IC cells, cached call targets ................. weak, like FeedbackVector slots (v1 §5.5)
```

- **AOT frames** use the canonical frame (H14) and the same spill trampolines. The scan treats them like JIT frames. No stack maps are needed while the heap does not move [R05].
- **VM-stack rule.** A JIT or AOT frame may keep its register file on the VM stack (D21). Then every slot still holds a valid Value. Unboxed values stay in machine registers or native spill slots.
- **pc->code registry (H14).** It maps a pc to JIT code or a unit range. It serves unwinding, Error.stack, the profiler, the debugger and deopt. The GC does not use it to find roots.
- **Weak IC cells.** When a shape or call target dies, its RW cell is cleared. A baseline-AOT IC then misses and refills the cell. An optimized-AOT guard takes its H32 policy path. No code is invalidated.
- **Moving nursery (not planned).** If one is ever added, JIT and AOT frames switch to precise maps. The maps come from the H29 deopt metadata [R05].
- **Scope.** Each isolate scans only its own thread's stack, at a safepoint. Helper threads never scan stacks (D14).

What the CSS probe found, and how ep9 covers each case [R05]:

| Probe case | Finding | ep9 rule |
|---|---|---|
| S1-S3 | References in registers are missed without a spill. LLVM keeps interior and one-past-end pointers live | Spill trampoline per ABI. Interior lookup through VO bits. Call-only safepoints |
| S4-S5 | Compressed 32-bit references | Not used (no pointer compression) |
| S6 | High-tagged NaN-box pointers are invisible unless untagged | Not reachable here: the JSC encoding stores cell pointers untagged. Encoded doubles start at 2^49, so they never fall in the cage |
| S7 | A reference held only in a Rust `Vec` is invisible | `Global<T>` or `ScratchRoots`, plus a lint that bans `Vec<Local>` |

The same rules cover AOT code: ep9_masm emits it, so call-only safepoints hold there too.

## 3. Barrier (one fast path in every tier and code kind)

**Decision (H11, 2026-10-20).** ep9 uses the JSC Riptide barrier. One object-granularity barrier serves sticky-mark generations (S1) and concurrent marking (S2). S2 marking is incremental update with a retreating wavefront. It is not SATB. The filter tests the new value only. New objects are white. Termination rescans all roots with the world stopped, including the conservative stack scan and the dirty cards of large arrays [R05] ([H11](../adr/H11-barrier-and-atomics.md)).

```
store(host, slot, v):                     // same shape in T0, Rust, T1, T2/T3, baseline-AOT, optimized-AOT
    if is_cell(v) && host.gc_state <= isolate.barrier_threshold {   // u8 values, unsigned compare
        barrier_slow(host, slot, v)        // cold, out of line; it does the store
    } else {
        slot.store(v, Relaxed)
    }
```

```
Rust setters, builtins, T0 handlers (ep9_vm) ---------+
T1 and baseline-AOT      (ep9_baseline, one emitter) -+--> same fast path --> barrier_slow(host, slot, v) in ep9_heap,
T2/T3 and optimized-AOT  (ep9_opt, one emitter) ------+    (threshold at a      reached through the isolate
                                                            fixed isolate offset) table (Runtime relocation)
```

| gc_state (word0 byte 4) | Value | Meaning |
|---|---|---|
| BLACK | 1 | Old (mark bit stuck) and not remembered. In S2: scanned |
| WHITE | 2 | Young: allocated since the last GC. Every allocation writes WHITE |
| GREY | 3 | Remembered (S1) or queued for a revisit (S2) |

| barrier_threshold | Value | Stage | Effect |
|---|---|---|---|
| OFF | 0 | S0 | No host fires |
| GEN | 1 | S1, and S2 between cycles | BLACK hosts fire |
| MARKING | 0xFF | S2 while marking runs | Every host fires. The slow path fences, then reads the state |

- **Cost (measured, rustc 1.99 -O3).** aarch64: cell test (2 instructions with the mask in a pinned register, 3 without) + `ldrb, ldrb, cmp, b.ls` + `str`. x64 SysV and Win64: 3 + 4 + `mov`. A value known to be a cell skips the cell test. A value known to be a non-cell needs no barrier (E1).
- **Why the new value only.** Incremental update needs a barrier only when a store makes a new edge. A store that deletes an edge is safe, because the final fixpoint rescans the roots. "Old only" misses new edges (unsound for S1 and S2). "Old OR new" is sound but adds a load and is not needed.
- **Why the slow path does the store.** The check runs first. While marking runs, every host fires, and the slow path does `store (Release); fence (SeqCst); load gc_state`. That is Riptide's store-then-check order. A check before the store without a later re-check loses objects (H11 model).
- **Emitter rule.** No GC point (call, safepoint poll, allocation slow path) sits between the check and the store. A loaded threshold or gc_state is never reused across a GC point. A stale GEN threshold while marking runs is the "check before the store, no re-check" failure of the model.

**Slow path.** It never allocates on the GC heap and never reaches a safepoint.

| Stage | barrier_slow(host, slot, v) does | It logs |
|---|---|---|
| S0 | Store | Nothing (threshold OFF; reached only in tests) |
| S1 (GEN) | Store. Large array (LOS): dirty the 512-byte card of `slot`. Else, if host is BLACK: set GREY and push host to the remembered set | The host. Cards for large arrays. Never the old value |
| S2 (MARKING) | Store with Release. `fence(SeqCst)`. Large array: dirty the card; if the host is BLACK and marked, also set GREY and push it once to the mutator mark stack, for a card-only revisit. Else, if host is BLACK and marked: set GREY and push host to the mutator mark stack. If host is BLACK and not marked (full cycle): CAS BLACK->WHITE, then set BLACK again if it became marked (JSC race fix) | The host, for a revisit near the end. Never the old value |
| S3 (later) | As S2. Also record `slot` when `v` is in an evacuation-candidate block | Plus candidate slots |

- **Marker rule (S2).** `obj.gc_state = BLACK; fence(SeqCst); read the fields`. With parallel or stealing markers, field loads use Acquire, or the marker issues an acquire fence after it scans an object and before it publishes the children to a shared deque. Revisits from the mutator mark stack drain last. Large arrays: clear a card, fence, then scan its range.
- **Cycle start.** A full cycle empties the S1 remembered-set buffer when it starts. Mark bits are cleared by epoch.
- **Termination (S2).** Stop the mutator at a safepoint. Retire the TLAB, so the VO bits cover bump-allocated objects before the conservative scan. Run every root source again: CSS of the native stack (spill trampoline), VM stack, `Global<T>` table, `ScratchRoots`, unit RW link cells, embedder roots, the mutator mark stack, the dirty cards of marked large arrays, weak and ephemeron constraints. Drain. Stop when no source adds work, with the world stopped. Else drain more or resume the mutator; a space-time scheduler decides (Riptide). No minor GC runs while marking runs.
- **Why the cards are a root source.** A card that the mutator dirties after the marker's last scan of that array is otherwise never scanned again, and its referent is freed (H11 critic model: `decided LOST C`; rescan or push: ok).
- **Allocation colour.** WHITE in every stage, also while marking runs. The final fixpoint marks every live new object. The end of the cycle frees new objects that it did not reach (no floating garbage).
- **Shape install.** A ShapeId store into word0 is a barriered store. The new shape cell is the value. It uses `barrier_slow_shape(host, shape_id)`.
- **Weak reads.** No read barrier. WeakRef deref, weak atoms, weak transitions, IC cells and JIT weak constants need none. Root rescans and the store barrier cover them.
- **Weak slots.** Every minor GC (S1) and every S2 end phase clears each weak slot whose referent is unmarked: unit RW IC cells, cached call targets, weak transitions, weak atoms, WeakRef targets and JIT weak constants. For young referents, the minor GC finds old weak slots through the remembered set and the RW range hook.
- **Unit RW data.** RW cells are roots. They take no write barrier. Link cells are strong; every fixpoint and every minor GC rescans them. IC cells are weak (see "Weak slots").
- **JIT code constants.** The strong pool is traced as fields of the code cell. A patch after the code is published uses the store barrier with the code cell as host. Weak constants are cleared or deopted at the end of marking and at every minor GC.
- **Bulk copies.** One check per destination host. The slow path copies with Release, fences once, then re-checks the host or dirties the cards.
- **Large element arrays** (LOS, above about 8 KiB) use 512-byte cards in the slow path. The fast path does not change.
- **JIT and AOT inline allocation** uses the TLAB `{cursor, limit}` at a fixed isolate offset (S1).

**Elision rules.** The barrier version covers them.

| ID | Rule | Why it is sound |
|---|---|---|
| E1 | The compiler proves that `v` is not a cell: plain store, no barrier | S1 and S2 track only new cell edges |
| E2 | The host was allocated in this code region, no GC point (call, poll, allocation slow path) has run since, and the host has not escaped (not stored into an object outside this rule, not passed to a call): plain store | The host stays WHITE until a GC point (S1). The concurrent marker can reach it only after it escapes, and the escaping store goes through `barrier_slow`, whose Release store publishes the earlier fields (S2) |
| E3 | Stores into roots (native stack, VM stack, `Global<T>`, `ScratchRoots`, unit RW cells): no barrier | Every minor GC and every S2 fixpoint rescans them |
| Not allowed | Drop a barrier because an earlier store to the same host had one | The marker can blacken the host between the two stores (JSC DFG escape note) |

- **Barrier version (H11, H35).** `BARRIER_VERSION = 2`. It covers the fast-path shape (check, then a slow path that stores), the new-value filter and `NOT_CELL_MASK`, the gc_state offset and values, the threshold offset, the slow-path entries `barrier_slow(host, slot, v)`, `barrier_slow_shape(host, shape_id)` and the bulk entry, the emitter rule, the elision rules E1-E3, and the TLAB offsets. On a mismatch the loader rejects the unit text and runs the unit's bytecode [R11][R14].
- Slow-path semantics (S1, S2, S3, card size, fences) need no new version, because units call the slow path through the isolate table [R05].
- **Proof.** The barrier model test, the remembered-set verifier V1 and the end-of-marking verifiers V2 and V3 (§7, H11).

## 4. Stages

| Stage | Algorithm | Barrier slow path | Milestone | Exit gate |
|---|---|---|---|---|
| S0 | Stop-the-world non-moving mark-sweep in mark-region style. Lazy per-page sweep. Bump allocation into free lines. LOS above about 8 KiB | Present; it only does the store (threshold OFF) | M0 | SP-GC: 0 missed objects in 10^6 random safepoints per ABI. The test262 pass set is identical under GC-stress. Verifier clean |
| S1 | Generations through sticky mark bits. Minor GC traces from roots plus remembered hosts plus dirty cards, then clears weak slots to dead young objects. TLAB `{cursor, limit}` at a fixed isolate offset | Remember BLACK hosts (BLACK -> GREY). Dirty 512-byte cards for large arrays | M1 | At M2: Splay ≥ 1.0x node --jitless. GC share of Splay time ≤ 25% (est.; Boa spends 35-50% [R07]). V1 clean under GC-stress |
| S2a | Parallel work-stealing marking. Concurrent sweeping | Same | M2 | GC share of Splay time below S1's |
| S2b | Concurrent retreating-wavefront marking on helper threads (JSC Riptide): white allocation, stop-the-world fixpoint that rescans all roots (CSS and dirty LOS cards included), space-time scheduler. Cooperative safepoint polls (back-edges, allocation slow path, long builtins). Shape-transition protocol (H21) | Threshold MARKING: Release store, SeqCst fence, re-grey BLACK hosts; a BLACK LOS host dirties a card and is pushed once. No weak read barrier | Built in M5. Functional before M7 starts | **Before M7:** GC-stress with verifiers V2 and V3 after each cycle; 0 verifier failures on test262 and v8-v7 under `--force-tier=baseline`. **By M8 exit:** the same under `--force-tier=opt` and `--force-mode=aot-baseline`, plus `aot-opt` and `hybrid` if they ship (K-A4J, K-A4P). p99 pause on Splay ≤ 5 ms (Riptide reports < 3 ms [R05]). TSan clean over 1,000 CPU-hours of stress. loom tests pass |
| S3 | Opportunistic Immix evacuation of sparse blocks. Objects pinned by CSS, FFI or Node-API are skipped. No concurrent compaction, ever (N9) | Forwarding through word0 | M8 (M5 if a G7 cap fails at M2) | RSS on the JetStream 3 JS subset ≥ 15% below S2 (est.) |
| S4 | Optional: read-only snapshot space, shared heap for workers, sandbox | n/a | Only if D6/D14 choose it | Per chosen item |

**TSan cannot see JIT or AOT code.** So the verifier gates (V1-V3) cover their stores and inline allocation [R05].

## 6. Snapshot interaction

```
build:   ep9 snapshot build -> blob { roots[n], realm intrinsics[j], atoms[k], fuses[f], root shapes[s] }
                                     ^ stable indices, deterministic layout (H13)
start:   map blob -> deserialize -> rewrite pointers -> fill isolate root table -> load units
unit:    text --RootIndex(n)--> isolate root table -----------------------------> object
         text --LinkSlot(i)---> RW link cell (resolved at load or first run) ----> object
         text --IcCell(i)-----> RW IC cell (filled by the IC, weak) -------------> shape / target
```

- The A1 snapshot (M4) holds intrinsics, JS shims, atoms, fuses and snapshot root shapes, all with stable indices (H13). [./07-runtime.md](./07-runtime.md) owns A1.
- Deserialization rewrites pointers. This works on a non-moving heap [R09].
- A deterministic snapshot layout gives stable ShapeIds for snapshot root shapes only (H8) [R17].
- Units reference snapshot objects only through root or intrinsic indices, or through link cells.
- The read-only snapshot space stays in S4. App heap snapshots come after v1.

## Changes vs plan v1

- Roots add AOT frames (conservative) and unit RW data (precise; link cells strong, IC cells weak).
- New VM-stack rule for frames that keep register files there (D21).
- The barrier rule covers baseline-AOT and optimized-AOT code. The unit header carries a barrier version; a mismatch falls back to bytecode.
- Contract items add: no heap address in units, the ShapeId rule, the unit RW visitor hook, one external-reference table, and the code range.
- New: snapshot-interaction section and the per-mode GC test matrix.
- The S2b "by M8 exit" gate adds the forced AOT modes. TSan note covers AOT code.
- Unchanged: the "hybrid like JSC" answer, stages, gates, MMTk position and probe rules.
- H11 decided (2026-10-20): JSC Riptide barrier; S2 is retreating wavefront, not SATB; new-value filter; slow path does the store; white allocation; stop-the-world root rescan incl. dirty LOS cards; weak slots cleared at every minor GC; elision E1-E3; verifiers V1-V3; barrier version 2. The WeakRef read barrier is dropped.
